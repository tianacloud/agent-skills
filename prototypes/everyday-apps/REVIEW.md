# 日常应用交互原型 · 已确认

打开 `index.html`，使用顶部导航切换三个应用。默认进入空白个人空间，点击「体验示例」可以浏览有内容的状态；两个空间分开保存。原型通过浏览器 localStorage 保留编辑内容，原型本身不连接云端。正式应用模板见下方 skill。

| 应用 | 设计与范围 | 冷启动 |
| --- | --- | --- |
| 拾账 · 账单 | 个人收支；月份切换、筛选、新增/编辑/删除、分类统计；蓝色账本 | 常用分类直达，只需金额就能保存；真实统计从零开始 |
| 一页 · 记事本 | 自动保存、全文搜索、分类、置顶、新增/编辑/删除；淡紫色列表与白纸编辑区 | 空白、随手记、会议记录、灵感四种入口，生成可编辑草稿 |
| 朝夕 · 日历 | 月历、日程列表、日期选择、单日定时日程新增/编辑/删除；暖橙色月历 | 阅读、散步、聚餐建议，选中日期后直接填写日程 |

## 建议体验

1. 每个应用先从空白状态新增一条记录，再刷新验证。
2. 切换示例空间，体验筛选、搜索、编辑、统计和跨月浏览，再切回自己的记录。
3. 缩窄至手机宽度，体验记事本的列表返回、日历选日与记账表单。
4. 顶部「重置当前原型」可单独重置当前应用、当前空间。

## 正式 skill

三个独立 skill 已制作：[拾账](../../skills/tiana-ledger/SKILL.md)、[一页](../../skills/tiana-notes/SKILL.md)、[朝夕](../../skills/tiana-calendar/SKILL.md)，沿用现有备孕、学习应用的完整模板交付方式。真实业务数据必须存入 Tiana SQLite，源码、锁文件、SQL 必须保存到 Tiana Git，托管版本关联对应源码提交；使用现有 provider-only 账户认证流程与 launcher 提供的路由环境。正式模板以零记录开始，建议与模板不冒充用户记录。

当前日历范围是单日定时日程；提醒、循环和外部日历同步尚未设计。账单按个人收支记账理解，当前不包含报销或发票流程。正式模板已实现 SQLite 持久化，服务部署与托管验收由创建应用时的目标环境决定。

## 本轮验证

- `npm run validate:ci` 六项校验通过。
- Chromium 实际操作通过：三个应用新增/编辑/删除、刷新保留、示例与个人空间隔离、搜索/置顶、结束时间校验、月份切换和重置取消。
- 检查 1440、390、320 像素宽度，页面无横向溢出；手机搜索返回列表、编辑返回列表与选中日期新建日程通过。
- 此验证针对交互原型，不代表 Tiana 云端接入或部署验收。
